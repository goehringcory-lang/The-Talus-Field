# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project shape

This repo contains three subsystems for **The Talus Field**, a Yosemite editorial site and field guide product. They are intentionally co-located so a single change (e.g. brand rename, copy update) can touch all three at once.

| Path | What it is | Stack |
|---|---|---|
| repo root (`*.jsx`, `index.html`, `styles.css`, `bodies/`, `img/`) | **Editorial site** at `thetalusfieldjournal.com`: articles, interactive trip-planner map (`/map`), film archive (`/films`), packing checklists. Static, no bundler. | Vanilla React: `*.jsx` sources precompiled into `/dist/*.js` by `scripts/gen-compiled.mjs` (`index.html` loads the dist files); styled with hand-written CSS in `styles.css`. Edge SEO via the root Worker entry `edge/seo.js` (see `wrangler.jsonc`); response headers/CSP in `_headers`. |
| `apps/guide/` | **Field Guide PWA** at `talus-field-guide.pages.dev` (the custom domain `guide.thetalusfieldjournal.com` is deliberately unattached until launch). Account-gated **paid product** ($3.99 one-time, 18-month access; see "paid model" below), offline-capable. | Vite + React 19 + TypeScript + react-router-dom + zod. |
| `workers/` | **API** at `api.thetalusfieldjournal.com`. Auth, Stripe checkout/webhook, KV-backed buyer records, contact form, IndexNow, NPS programs feed (`/api/programs` + daily cron), NWS weather proxy (`/api/weather`), trip-link email (`/api/trip/email`). | Cloudflare Worker + Hono + `@tsndr/cloudflare-worker-jwt` + KV. |

DEPLOY.md has a full deployment runbook (its "buy box / Field Guide launch checklist" is the current 8-step go-live sequence). Note that DEPLOY.md was written against the older trip-based PWA model (`1day`/`3day`/`5day`, "35 stops"). The PWA was since refactored to region-based (`valley`/`glacier-mariposa`/`tuolumne`/`hetch-hetchy`, ~44 core stops); treat the smoke-test section as directionally correct but stale on specifics. `CONVERSION-STRATEGY.md` (July 2026) is the current reader→subscriber→buyer growth plan, successor to `GROWTH-AUDIT.md`.

## Common commands

Local dev hosts (matches `.claude/launch.json`):

```bash
# Editorial site — port 8765
python -m http.server 8765

# PWA — port 5173
npm --prefix apps/guide run dev

# Worker — local dev
cd workers && npm run dev      # = wrangler dev
```

Build / typecheck / checks:

```bash
npm --prefix apps/guide run build       # tsc -b && vite build → apps/guide/dist
npm --prefix apps/guide run lint
npm --prefix workers run typecheck      # tsc --noEmit

bash scripts/check-cache-busters.sh     # editorial: ?v= and BODY_VERSIONS sync
npm --prefix scripts run seo:check      # editorial: SEO mirror freshness
npm --prefix scripts run seo            # regenerate SEO mirrors
npm --prefix scripts run compile        # editorial: recompile *.jsx → /dist/*.js (run after any jsx edit)
npm --prefix scripts run home-shell     # editorial: rebake the static homepage shell into index.html
npm --prefix scripts run prerender      # editorial: regenerate /prerender article fragments
npm --prefix scripts run archive        # editorial: rebuild /archive from nature-notes/ (512 Nature Notes issues)
npm --prefix scripts run check          # editorial: all pre-commit guards (cache-busters + seo + prerender + compile + archive checks + guide archive citations + guide photos + intent tags)
npm --prefix scripts run archive:citations  # guide: every stop's Nature Notes citation resolves to a real archive page
npm --prefix scripts run photos:check   # guide: every referenced photo exists with its responsive ladder, + photo-pass inventory
npm --prefix scripts run intent:check   # editorial: article intent tags match the catalog, and every trip-selector answer set builds a real plan
npm --prefix scripts run itineraries:check  # guide: every prepackaged plan seeds and slots into a runnable day
npm --prefix scripts run images         # regenerate responsive image variants (sharp)

npm --prefix scripts run checks         # editorial: offline system-checks suite (SEO/render/distribution)
npm --prefix scripts run checks:online  # + link liveness, sitemap 200s, template smoke, SPF/DKIM/DMARC
```

Dev tooling lives in `scripts/` with its own `package.json`, deliberately not at the repo root, so the root stays a static, build-free deploy. Run `cd scripts && npm install` once before using the npm scripts above. The root `package.json` is NOT a tooling home: it exists only because the Cloudflare Workers Build for the editorial worker runs `npm run build` before deploying, and its `build` script is a no-op echo. Do not add dependencies or real build steps to it (`.assetsignore` also excludes it from the asset upload).

Deployment is **not** done from this repo's CI. On merge to `main`: the **editorial site** deploys via a git-connected Cloudflare **Workers Build** (root `wrangler.jsonc`; it runs the root `npm run build` shim then `npx wrangler deploy`, uploading the repo root as static assets with `edge/seo.js` as the Worker entry); the **PWA** deploys via the git-connected Cloudflare **Pages** project `talus-field-guide` (root dir `apps/guide`, build `npm run build`, output `dist`, Node pinned by `apps/guide/.nvmrc`). The **API Worker** never auto-deploys: it requires a manual `wrangler deploy` from `workers/` (with KV namespace IDs filled into `wrangler.toml` and secrets set via `wrangler secret put`).

## Editorial site conventions

- **No bundler, but a compile step.** The `*.jsx` files at the root are the source of truth, but the browser loads the precompiled `/dist/*.js` versions (no in-browser Babel). After editing any root or `bodies/` jsx, run `npm --prefix scripts run compile` and commit the regenerated `dist/` files alongside the source; `npm --prefix scripts run check` fails if they drift. Edge SEO head rewriting is done by `edge/seo.js`, the root Worker's fetch handler (ported from the retired Pages Function `functions/_middleware.js`); it also injects crawler prose for hub routes (`HUB_PROSE`) and serves unknown paths as real 404s.
- **Static homepage shell (July 2026 LCP pass, part two).** `/` ships its above-the-fold markup — masthead plus hero — as plain HTML inside `index.html`, between the `GENERATED:HOME-SHELL` markers, so it paints on the first byte instead of waiting on the SPA boot. `scripts/gen-home-shell.mjs` (`npm --prefix scripts run home-shell`, guarded by `run check`) renders it from the **real** `Header` and `HomeHero` components, so it cannot drift from what React draws a moment later; React replaces it on boot and `app.jsx` removes any leftover `#home-shell`. Three rules: (1) `HomeHero` must render without browser APIs on its first pass, since the generator has no DOM; (2) nothing date-derived may be baked in — the hero issue label is blanked to a stable-height placeholder and filled by React, and the generator fails loudly if the slot disappears (`DATE_SLOTS`); (3) `/` is served straight off the asset layer and never invokes the Worker (see `wrangler.jsonc`), which is why the shell lives in `index.html` and `edge/seo.js` *strips* it on every other route. The sr-only `#seo-static-h1` moved out of `index.html` into the Worker for the same reason — the homepage now has a real `<h1>`.
- **Route-level lazy loading (July 2026 LCP pass).** `index.html` eagerly loads only the shared shell: the self-hosted React UMD files under `/vendor`, `storage.js`, `affiliate.js`, `data.js`, `dist/tweaks-panel.js`, `dist/components.js`, `dist/app.js`. Every `page-*.js` bundle (plus `videos-data.js`, `itineraries-data.js`, and the `intent-data.js` / `dist/intent.js` pair) loads on demand via `PAGE_MODULES`/`ensureRoute` in `app.jsx`: the active route's bundle before first render, the rest prefetched on first user interaction. **Adding a page means registering it in `PAGE_MODULES` (app.jsx), not adding a `<script>` tag to index.html.** Injected scripts reuse the shared `?v=` (read from the app.js tag), so the cache-buster discipline is unchanged. Only two Google Font families load (EB Garamond + Inter); don't reintroduce the others.
- **Monetization pass (July 2026, MONETIZATION-IDEAS.md).** New evergreen routes: `/firefall`, `/tioga-opening`, `/half-dome-lottery` (event decision-aid pages — no year in URL or copy; each links its dated deep-dive article, which links back), `/consult` (paid trip consults; the two placeholder consts at the top of `page-consult.jsx` take the owner's Stripe Payment Link + booking URL, mailto CTA until then), `/widget` (embed pitch page). Lodging/camping affiliate networks (MONETIZATION-IDEAS.md 3.1): `affiliate.js` registers `expedia` (LIVE — the Expedia Group Travel Creator camref, Partnerize `prf.hn` wrapper; this is what the article lodging links use), plus `booking`, `stay22`, and `hipcamp` with empty ID consts that fail soft to plain outbound links until approved IDs are pasted in — mirror any ID change in `scripts/gen-prerender.mjs`, which duplicates the builders for prerendered fragments. The money articles (where-to-stay, gateway-towns, camping, trip-cost, plus the kids and pets pieces) carry disclosed availability links through the shared `AvailabilityLink` / `LodgingCta` components + `AffiliateNote`; the guardrail (best recommendation stays top, linkless, if unaffiliated) is published on `/affiliate`. The August 2026 optimization pass on top: (1) placement-level GA4 `aff_list` values — `article_cta` / `article_inline` / `article_town` / `trip_selector` / `stay_banner` plus the page-level names, full inventory in ARCHITECTURE.md — so never reuse the retired bare `article`; (2) `LodgingCta` has an optional `image`/`caption`/`credit` figure slot (photo must show the place the link searches; markup mirrored by hand in `gen-prerender.mjs`); (3) `buildTripPlan` returns a `lodging` field (only when the stay answer is `undecided`/`gateway`) that intent.jsx renders through `LodgingCta`, asserted across all 18,200 combinations by `check-intent-tags.mjs`; (4) `ExpediaBanner` (components.jsx) renders Expedia's licensed banner creative from the fail-soft `window.EXPEDIA_BANNER` consts in `affiliate.js` — one placement on `/stay` only, plain `<img>`+`<a>`, never a script/iframe (CSP), and not in the prerender sandbox. Shared `/map?trip=` links get per-trip OG cards: `scripts/gen-og-cards.mjs` pre-generates `img/og/trip-{1..20}.jpg`, `gen-seo-artifacts.mjs` emits the `trip-points.json` `{id: name}` mirror, and `edge/seo.js` overrides title/description/og:image (canonical stays `/map`; `ogUrl` carries the shared URL). `edge/seo.js` also has a `REDIRECTS` table (301s, checked before `seoForPath`) — empty until a slug is retired.
- **Navigation (July 2026 pass, simplified in the July 2026 nav-simplification pass).** Two tables in `components.jsx` are the site's map. `NAV_GROUPS` is the masthead bar, now four items: Plan a Trip (mega dropdown) / Conditions (plain link) / Explore Yosemite (mega dropdown, key `read`) / Field Guide (plain link), each dropdown a column set of `{ key | href, label, note }`. `NAV_SECONDARY` is everything that left the bar (About, Newsletter, Films, the `/archive/` href, Directory, Advertise, Widget, Group codes, Contact): it renders in the hamburger's More section and is mirrored by the footer and `/explore`, never the bar. Constraints on both tables: nothing date-derived and nothing computed from the catalog may appear in the copy (the masthead is rendered into index.html's static home shell by `gen-home-shell.mjs`, which runs with an empty `window.ARTICLES` and fails the build on a leaked year), an entry with `href` instead of `key` is a real navigation and must never get a `go()` handler (that is how `/archive/` is linked), and a route belongs to exactly one table. Search is a top-level masthead destination, not a dropdown item, and the hamburger carries a real query box that pushes `/search?q=` before the route commits. **`BottomNav`** (also `components.jsx`, rendered by `Header` so it bakes into the home shell) is the phone-width persistent bottom tab row — Plan (`/planning`) / Now (`/now`) / Map (`/map`) / Read (`/articles`) — shown at the same ≤880px breakpoint where the inline nav collapses; it returns `null` on `/map` and `/guide`, whose bottom edges belong to the map sheet and the buy bar, and `body:has(.bottomnav)` supplies the content clearance. **`/explore` is the site index** (`page-explore.jsx`): every reader-facing destination with a line on what it is, counts drawn live from the catalog, linked from the hamburger, the footer, the 404 page, and `/search`. **`KEEP_GOING`** (also `components.jsx`) is the curated onward-links table keyed by route; `app.jsx` mounts `<KeepGoing>` once under `<main>`, so a page ends in three or four deliberate next steps instead of nothing. A route absent from the table renders nothing — articles have their own related rails, and the home and legal pages want no block. Breadcrumbs are on every standing page.
- **Reader intent: the trip selector and the filters (July 2026).** `/planning` and `/articles` were long sequential lists that only worked if the reader recognised which title answered their question. Two files fix that, both loaded only on those two routes (`PAGE_MODULES`), never in the eager shell: **`intent-data.js`** (raw, uncompiled, like `itineraries-data.js`) carries the taxonomy and the logic, and **`intent.jsx`** (`/dist/intent.js`) carries the React. Three fixed facets — `stage` (before booking / dates set / week before / in the park now), `who` (first trip, families, non-hikers, accessible, dogs, backpacking, photography), `topic` (lodging, camping, permits, transportation, food, trails, conditions) — with `window.ARTICLE_INTENT` tagging every article by hand. Selections are **OR within a facet, AND across facets**, mirrored into the URL with `replaceState` so a filtered view is a shareable link, and each chip's count is scoped to the *other* facets so it dims to zero honestly instead of promising results it cannot deliver. On `/planning` an active filter replaces the five curated parts with matches from the **whole** catalog (a reader who filters for camping wants the camping guide whether or not it earned a slot in the curation); on `/articles` the intent bar composes with the existing section chips. Four things are load-bearing: (1) an empty facet on an article is a legitimate answer, not an omission — the natural-history essays answer no logistics question and a made-up `topic` tag would put one in front of a reader who asked about permits; (2) `window.ARTICLE_MONTHS` is NOT a facet, it exists only so the trip selector stops recommending "Yosemite in June" to a February trip, and every month's `TRIP_MONTHS.read` anchor must be inside its own month's window or the table would drop the anchor it is protecting; (3) `relaxIntent` loosens a selection until it returns between six entries and half the archive, because the honest intersection of five answers is usually empty and half the catalog is not a narrowing — stage-only is deliberately not on the ladder, since dropping the traveler to buy a bigger number throws away the reader's strongest signal; (4) `scripts/check-intent-tags.mjs` (in `npm --prefix scripts run check`, `run intent:check` for the verbose form) is the only thing that can catch drift — an article added without a tag entry is simply invisible to every filter, which reads to a visitor as "the site has nothing on that". It also sweeps all 18,200 trip-selector answer combinations and fails if any produces an empty read list, an itinerary id the itineraries data does not define, or a product route that is not real.
- **The five-question trip selector** sits at the top of `/planning`: when, how many days, where you are staying, who is traveling, what matters most. The plan appears only when all five are answered (a plan built from two answers is a guess wearing a plan's clothes), and it returns a read list, a day plan, and a paid product. Three rules in `buildTripPlan`: it is **deterministic** (no dates, no randomness — same answers in, same plan out); the itinerary is **capped to what the month's roads allow** and says so, because day two of the two-day plan is Glacier Point Road and day three of the three-day plan is Tioga Road, and handing a January visitor a route over closed gates is the exact failure this site exists to prevent; and the **paid product follows the trip, not the sale** — the Field Guide is the default, `/consult` only for the plans with real constraints (four-plus days, access needs, unbooked peak-season dates), and never for a half-day or budget-focused trip. Answers persist in `tfg.trip.selector` and mirror to `?when=&days=&stay=&party=&focus=`, with the URL winning on mount so a shared plan link shows the sender's plan. The month table (`TRIP_MONTHS`) is a **sibling of, not a copy of**, `page-home.jsx`'s `MONTHS`: the homepage describes what a month is like, this one records what it decides (`tioga`/`glacier` = `open` | `closed` | `unsettled`), which is what drives the itinerary cap.
- **The Planning Guide's five parts** (`PLANNING_PARTS` in `page-planning-guide.jsx`) own the copy but not the membership: the slugs come from `window.PLANNING_SERIES` in `data.js`, which the article pages already read for their "part of the Planning Guide" series band. One list, so the page and the band cannot disagree about what is in Part Three; the coupling is by exact part label, and `check-intent-tags.mjs` fails if a label stops resolving (it would render a part with no articles under it).
- **Site search (`/search`)** is client-side over `window.ARTICLES` plus a hand-maintained list of standing pages in `page-search.jsx` — no index file to fetch, no third-party widget. It searches **titles, deks, and section names, not article bodies**: bodies are lazy-loaded per slug, so a full-text index would mean pulling all of them down or shipping a fourth generated mirror. The page says so rather than letting a body-text miss read as "the article doesn't exist". `?q=` is mirrored with `replaceState`, not `pushState`, so typing doesn't bury the previous page under one history entry per keystroke, and `edge/seo.js` marks the route `noindex, follow` (a results page is thin, duplicative content, and every `?q=` is another near-identical URL) — which is also why it is NOT in the sitemap table in `gen-seo-artifacts.mjs`, only in `STATIC_ROUTES` for link checking.
- **Trip hand-off to the Field Guide.** The map sidebar's "Open this trip in the Field Guide" links to `<app>/trip?import=<ids>`. The two catalogs overlap but are not identical (`points.geojson` was seeded once from the guide's stops, and several editorial pins match a HIKE id rather than a stop id), so `apps/guide/src/trip/importTrip.ts` resolves alias → stop → hike and **reports what it could not bring across rather than guessing** — a wrong turnout is the failure this product exists to avoid. Ids are also stashed at PWA boot (`tfg.trip.pendingImport`, 30-day TTL) because a reader who does not own the guide yet leaves for Stripe and returns through `/open?token=`, which knows nothing about the trip; Home then offers it, and only an explicit tap writes to the plan.
- **"The Park Bulletin" (`/now`)** is the one-page everything-happening board (it replaced the weekly "This Week in the Park" dispatch in July 2026): the current NPS Yosemite Guide edition condensed into alerts, road/area status, the free-program clock, dated events (auto-dimmed once past), trail status, hours, transit, and phone numbers. Content lives in `bulletin.json`, rewritten once per Guide edition (~every 5 weeks; see its `__comment` for the workflow), rendered by `page-now.jsx` (`BulletinPage`; own `?v=` counter on `BULLETIN_URL` shared with `HOME_BULLETIN_URL` in `page-home.jsx`, like the map's `POINTS_URL`), served to non-JS crawlers via the `HUB_PROSE` entry in `edge/seo.js`, and its sitemap lastmod tracks `edition.updated` automatically. It is a standing editorial commitment: carrying a stale edition past its end date without a note is worse than none.
- **Cache-buster discipline.** When you edit a JSX file or `styles.css`, bump its `?v=N` query in `index.html`. Cloudflare and browsers both cache aggressively otherwise. All page scripts and the stylesheet share one version number; bump them together to a new shared number when shipping a batch. `points.geojson` has its **own** `?v=` counter: the `POINTS_URL` const in `page-map.jsx` (exported as `window.POINTS_URL`, also consumed by `/itineraries`) — bump it separately when editing pins. Run `bash scripts/check-cache-busters.sh` before committing — it errors if any reference is missing a `?v=` or if `window.BODY_VERSIONS` is out of sync with `bodies/`.
- **Globals via `window`.** Each JSX file attaches its top-level component to `window` (e.g. `window.GuidePage = GuidePage`) so siblings can reference it. The list of `/* global */` comments at the top of each file declares what it consumes. The full `window.*` API surface, the GA4 event inventory, and the localStorage key inventory are documented in `ARCHITECTURE.md`. All localStorage access goes through `window.safeStorage` (storage.js), never `window.localStorage` directly.
- **Article bodies** live in `bodies/*.jsx` and are **lazy-loaded**, not registered as `<script>` tags in `index.html`. `data.js` indexes each article in `window.ARTICLES` and versions each body per-slug in `window.BODY_VERSIONS`; `window.loadArticleBody(slug)` injects the script on demand. When you add or edit a body, add/bump its `BODY_VERSIONS` entry.
- **SEO mirrors are generated, not hand-edited.** `data.js` (`window.ARTICLES`) is the single source of truth for the catalog; SEO enrichment the browser does not need (keywords, wordCount, FAQ, trail facts) lives in `seo-data.json` keyed by slug. `articles.json` (read by the edge SEO function `functions/_middleware.js`), `sitemap.xml`, `feed.xml`, and the article list in `llms.txt` are all generated by `scripts/gen-seo-artifacts.mjs`. After adding or editing an article (data.js + its body) and any enrichment (seo-data.json), run `npm --prefix scripts run seo`, then commit the regenerated files. Run `npm --prefix scripts run seo:check` (or `bash scripts/check-seo-artifacts.sh`) before committing — it fails if any mirror is stale. FAQ answers and trail numbers in `seo-data.json` must come from the article's published body; do not invent facts.
- **System checks suite.** `scripts/system-checks.mjs` (run via `npm --prefix scripts run checks`) is a health battery with one module per check in `scripts/checks/` (links, per-page SEO + og:image + Article JSON-LD, sitemap, feed, image hygiene, mirror freshness, template smoke, email-auth). It exits non-zero only on **error**-severity findings; length/size/keyword issues are **warnings**. Offline by default; `--online` adds link liveness, sitemap 200s, the template smoke test, and SPF/DKIM/DMARC DNS lookups. The catalog loaders are shared with `gen-seo-artifacts.mjs` via `scripts/lib/catalog.mjs` (one `node:vm` harvest of `data.js`). It runs nightly in CI (`.github/workflows/system-checks.yml`), which also records a Lighthouse Core Web Vitals trend to `scripts/data/lighthouse-history.json` (warn-only on regression). New-URL search-engine notification is **not** here — `indexnow.yml` already push-indexes on publish, and standalone Google/Bing sitemap pinging was retired in 2023. The committed baseline is `scripts/data/baseline-report.md`.
- **Map page** (`page-map.jsx`, `/map` route): Google Maps JS API trip builder over `points.geojson`. The API key sits in `index.html`, domain-restricted in the Google Cloud console; `mapId` is required by AdvancedMarkerElement. Pins are maintained **by hand** in `points.geojson` (it was seeded once from the PWA's stops via `scripts/seed-points-from-stops.mjs`; re-running overwrites the file). The trip persists in localStorage (`tfg.trip`) and is shareable via `/map?trip=id1,id2`. The **whole map** is newsletter-gated (`tfg.map.unlocked`): `MapAccessGate` covers the page over a blurred live map until one Buttondown signup (or any prior signup on the site) unlocks it; bypassable by design and fails open when storage is unavailable. Overlay controls (`Reset view`, `Find me` geolocation with a "you are here" dot) sit bottom-left of the map. A July 2026 UX pass added category filter chips (`?cat=` param, `CATEGORY_STYLES`), stop search, marker clustering (MarkerClusterer lazily injected from unpkg below zoom 13, fails soft to plain markers; unpkg is CSP-allow-listed), a peek/half/full mobile bottom sheet, and undoable trip-change toasts. Quick-pick itineraries are derived from `window.ITINERARIES`, and a "Email this trip to yourself" box (`TripEmailBox`) submits to Buttondown **and** POSTs `{email, stops, website}` to the Worker's `/api/trip/email`, which builds the share URL server-side and mails it via Resend.
- **Itineraries + Conditions pages** (July 2026). `itineraries-data.js` is a raw (uncompiled) script like `data.js`: it defines `window.ITINERARIES` (four plans: `1day`/`2day`/`3day`/`halfday`, each day listing `points.geojson` ids in drive order) and `window.getItineraryStopIds(id)`; it is the single source of truth for both `/itineraries` (`page-itineraries.jsx`, which fetches `window.POINTS_URL` to resolve stop names and links each plan to a real `/map?trip=…` navigation) and the map's quick picks. `edge/seo.js` carries a **hand-maintained** TouristTrip ItemList for `/itineraries` — keep it in sync when plans change. `/conditions` (`page-conditions.jsx`) is a bookmarkable link-out page (webcams, entrance waits, hardcoded NWS point-forecast links) reusing `WebcamStrip` and `EntranceWaits` from components.jsx; it fetches nothing itself. Adding a static route like these touches: `app.jsx` (`STATIC_ROUTE_KEYS` + render-switch branch + a `PAGE_MODULES` entry with the page's `globals` — NOT the `REQUIRED_GLOBALS` const, which is the eager shell only, and NO `index.html` script tag: page bundles lazy-load), the compile list in `scripts/gen-compiled.mjs`, `STATIC_ROUTES` in `scripts/lib/catalog.mjs`, the sitemap table in `scripts/gen-seo-artifacts.mjs`, an `edge/seo.js` `known[path]` entry (+ optional `HUB_PROSE` thunk), the **client-side** `known` table in `app.jsx`'s `buildSeo` (a route missing there falls back to homepage meta on SPA navigation — the bug that left `/search`, `/stay`, and `/partners` titled "The Talus Field" until the July 2026 nav pass), then a home in `NAV_GROUPS` and on `/explore`, then `npm --prefix scripts run compile && npm --prefix scripts run seo`.
- **The Nature Notes archive (`/archive`)** is the 1922-onward run of the National Park Service's *Yosemite Nature Notes* bulletin: 512 issues, ~1.87 million words, transcribed from the scans at yosemite.ca.us. Sources are the markdown in `nature-notes/` (excluded from the asset upload by the `*.md` rule in `.assetsignore`); `scripts/gen-archive.mjs` turns them into committed static HTML at `/archive/<year>/vol-<v>-no-<n>/`, plus year indexes, a landing page, its own `archive.css`, and its own `sitemap.xml` (referenced from `robots.txt` — 569 URLs would swamp the editorial sitemap). Parsing and text repair live in `scripts/lib/nature-notes.mjs`; read its header comment before touching either file. **These are NOT SPA routes** — they are real files served off the asset layer, so the Worker never runs for them, every page carries its own complete `<head>`, and any editorial link into the archive must be a plain `<a href="/archive/">` with no `go()` handler. `/styles.css` is linked without a `?v=` on purpose (it is served with a 5-minute TTL, and baking the shared version in would rewrite all 512 pages on every unrelated CSS tweak); `check-cache-busters.sh` only inspects `index.html`, so nothing is being smuggled past a guard. `--check` is wired into `npm run check`, as is `check-archive-citations.mjs`, which verifies that every `history` citation in the Field Guide's stops resolves to a real issue page here (see the PWA's "archive notes on stops"). Two decisions worth keeping: dates are read from each issue's own masthead on **page one only** (volume 40 number 1 reprints the July 1922 issue on page two, and a whole-document search dates it to 1922), and the earliest date on the cover wins over the most precise one (volume 17 number 3 reads "March, 1938" above a photo caption dated October 4, 1933). The 54 issues whose covers carry no legible date get their volume's median year and render a visible "(year inferred)" marker — never present an inferred date as a fact. Build stats and the full inferred-date list are in `scripts/data/nature-notes-report.md`.
- **Film archive** (`page-films.jsx` + `videos-data.js`, `/films` route): the NPS *Yosemite Nature Notes* series as `window.NATURE_NOTES`. Embeds are click-to-load facades — only the YouTube thumbnail loads until the reader presses play, then a `youtube-nocookie.com` iframe replaces it. `youtubeId` values were verified against the published uploads; do not edit one without checking the video it points to. Deks are original Talus Field copy, not NPS copy.
- **Responsive images.** `scripts/gen-responsive-images.mjs` writes AVIF/WebP/JPEG variants at several widths into sibling `responsive/` folders (under `img/` and `apps/guide/public/photos/`), slug-named so the in-browser `ResponsiveImage` helper derives URLs with no manifest. Run `npm --prefix scripts run images` after adding source JPEGs.
- **Photo ingest (house photography).** `scripts/ingest-photos.mjs` (`npm --prefix scripts run photos:ingest`) is the front door for photos shot by the owner; `fetch-guide-photos.mjs` remains the path for licensed Commons/Pexels acquisition. Drop camera files into the gitignored `photo-inbox/editorial/` (→ `img/`) or `photo-inbox/guide/` (→ `apps/guide/public/photos/`), then run the one command: it applies EXIF orientation, downscales, re-encodes as mozjpeg with **all metadata stripped**, runs the variants generator, records an "All rights reserved" credit for guide photos, and prints the `data.js` / `stops.ts` snippet. Four rules it enforces, each for a reason that bit or would have bitten: (1) `gen-responsive-images.mjs` never calls `.rotate()`, so a portrait phone photo dropped straight into `img/` comes out sideways in every variant — everything in the repo today was pre-normalized by `fetch-guide-photos.mjs`, which is why nothing has hit it yet; (2) both photo dirs deploy **wholesale, originals included**, so un-stripped EXIF publishes the camera's GPS fix — capture coords are logged to the gitignored `scripts/data/photo-exif-log.json` first, since they're useful for checking a stop's `coord`, and then destroyed by the re-encode; (3) camera-default filenames (`IMG_4823`) are skipped, because the pipeline has no manifest and the filename becomes the permanent URL key and the reference in `stops.ts`; (4) an existing target filename is an error without `--replace`, because `/img/*` is served `immutable, max-age=2592000` and reusing a name means up to 30 days of the old photo. `--dry-run` reports without writing. **Shoot JPEG, not HEIC** (iPhone: Settings > Camera > Formats > "Most Compatible"): sharp's prebuilt libvips omits the HEVC decoder, verified July 2026 against a real HEVC file. The trap is that nothing cheap detects it — `sharp.format.heif.input.file` reads `true` (the HEIF loader exists, for AVIF), and `metadata()` *succeeds* on a HEIC and reports `compression: 'hevc'`; only the pixel decode fails. The ingest checks `compression` and skips with instructions, and wraps the write so an undecodable file can't take down a batch. **Remote path (August 2026):** the same ingest also runs from `.github/workflows/photo-import.yml`. Photos uploaded from a phone via the Worker's `/photos` page stage untouched in the `talus-photo-inbox` R2 bucket (`workers/src/routes/photos.ts`, bearer-gated by `PHOTO_UPLOAD_TOKEN`; camera-default names and HEIC are rejected at upload); the workflow (triggered by `POST /api/photos/import` via `repository_dispatch`, or manually) pulls them into `photo-inbox/`, runs `ingest-photos.mjs`, and opens a PR with the ingest log and reference snippets — ingested files are cleared from the inbox, skips stay staged. The Worker never writes a photo anywhere the site serves from; setup runbook is in DEPLOY.md ("Remote photo upload").
- **CSP lives in `_headers`.** Any new third-party script, frame, or connect target must be allow-listed in the Content-Security-Policy there or it will be blocked in production (it works locally, which is the trap).
- **`page-guide.jsx` runtime URL overrides:** `window.GUIDE_API_BASE` and `window.GUIDE_APP_BASE` can be set in a console snippet to point at local dev (`http://localhost:8787` and `http://localhost:5173`) before the script loads.

## PWA architecture

- **Content model.** `apps/guide/src/content/schema.ts` defines `Stop` (zod schema) with a `region` enum: `valley` | `glacier-mariposa` | `tuolumne` | `hetch-hetchy`. `content/stops.ts` is the seed array, validated at module load via `Stops.parse(seed)` — schema violations throw in the Vite overlay or fail the build. `content/index.ts` exports `REGIONS` (the picker metadata), `REGION_SHORT` (chip-length labels), and helpers `getStopsByRegion`, `getStopById`, `getRegionMeta`. `content/itineraries.ts` defines 1/2/3-day presets whose day stop lists are derived live from `getStopsByRegion()` — adding a stop to a region flows through with no itinerary edit (the presets cover the original three regions; Hetch Hetchy is a la carte). `content/seasonal.ts` is the bundled seasonal almanac (full moons, road-opening windows, firefall): entries convert to ProgramEvent records (source `seasonal`, an enum value mirrored into the Worker schema) and merge into /programs client-side, so the agenda keeps an offline floor; `typical`-confidence entries are labeled as such everywhere they render.
- **Prepackaged plans and the clock (August 2026).** `content/itineraries.ts` presets carry one ordered `plan` per day — stop ids and day-hike ids interleaved in drive order, resolved by `resolvePlanEntry` (core stop, then hike, then hidden stop: `mcgurk-meadow` is deliberately both a hidden stop and a hike, and a preset naming it means the hike). The two arrays it replaced could only seed hikes after every stop, which put McGurk Meadow an hour back up the road it had just come down. **A day without a `plan` derives from `getStopsByRegion()`, which is a reading order, not a day** — the two days that relied on it lost Wapama Falls and Soda Springs to the capacity filter and put lunch at 6:54 p.m., so treat the fallback as a safety net, not an option. Sequence comes from the plan, but not every time: a stop whose `dayPart` (content/schema.ts) says the clock is a fact gets anchored by `trip/slotting.ts`. Three values, and the difference between the last two is load-bearing — `midday` (a meal) and `sunset` (a stop whose value is the last light, timed off `sun/solar.ts` so December anchors to 4:42 p.m. and June to 8:23) are **reserved before the day is filled**, so two seeded ranger programs move the day around them instead of walking lunch to 5 p.m.; `evening` (the meal on the way out) is only a **floor** placed last, because reserving a December dinner would sit it in front of the five-hour Wapama hike and push the hike off the day. `dayPart` is opt-in and narrow: a stop that is merely *better* early (Mirror Lake's reflection) carries none — that is the drive order's job. `apps/guide/scripts/check-itineraries.ts` (`npm --prefix scripts run check`, or `run itineraries:check`) seeds and slots every preset across five dates through the app's own modules, and fails on a lunch outside midday, a sunset stop that misses sunset, an entry the capacity filter drops, or an anchored stop pushed off the day. Midwinter is exempt from the everything-must-fit rule only (three and a half fewer hours of light); anchored stops are never exempt.
- **Archive notes on stops (July 2026).** A Stop may carry an optional `history`: one short, sourced note from the Nature Notes archive (see the `/archive` bullet above) with the citing issue's `volume`, `number`, and printed `issueDate`. `content/archive.ts` builds the link from those three values (`/archive/<year>/vol-<v>-no-<n>/` on the **editorial** origin, year taken off the end of `issueDate`), and `components/ArchiveNote.tsx` renders it under the body on the full read only (`StopCard` with `compact={false}`: the stop page and `/preview`) — a citation block on every card in a region list turns the list into a bibliography. Two rules, both load-bearing: **every fact in the note must come from the cited issue** (the citation is the whole point, and a reader who follows the link has to find what the note claims), and the link is an external one that will not open offline, which is why the note itself is bundled and only the source needs the network. `scripts/check-archive-citations.mjs` (wired into `npm --prefix scripts run check`) scans the seed files and fails if a citation points at an archive page that does not exist or that does not print the date the note claims — nothing at runtime can catch either.
- **Coords are web-verified, not ground-truthed.** A July 2026 pass checked every `coord` in `stops.ts` against NPS place/trailhead pages, USGS GNIS, and OSM-derived sources; each coord line carries its source and any prior offset. Stops still marked `// TODO: verify on the ground` (unsigned pullouts, off-trail features, conflicting sources) have no authoritative source; never strip those markers without a real field visit, because the field guide's value prop depends on accurate parking turnouts.

- **Trail tracks (July 2026).** Per-hike GPS tracks + elevation profiles in `apps/guide/public/tracks/<hikeId>.json`, generated by `scripts/gen-hike-tracks.mjs` (`npm --prefix scripts run tracks`; needs network, caches ~100 MB of USGS quads plus an Overture extract in the gitignored `scripts/data/.trailcache/`). - **Weather feature** (`src/weather/`). Same shape as programs: `schema.ts` mirrors `workers/src/lib/weather.ts` by hand, `useWeather` is network-first against `/api/weather` with a Cache API fallback (payload in `tfg-data` under a synthetic key, stamp in `tfg.weather.meta`). DST edges); `SunLine` renders on `/today` and as the always-present floor of `WeatherStrip` ("Weather & light"), the one deliberate loosening of the weather-renders-nothing rule, allowed only because computed sun times cannot be stale.

Session shape: `{ jwt, username }` — the JWT `sub` claim is treated as a string label and surfaced as `username` regardless of which Worker auth path issued it. The session is derived from the JWT itself (`sessionFromJwt`), not by re-reading localStorage, so sign-in works in storage-blocked browsers without burning single-use magic-link tokens.

- **Programs feature.** `src/programs/schema.ts` mirrors `workers/src/lib/programs.ts` (keep in sync by hand — no shared package on purpose). `usePrograms` is network-first against `/api/programs` with an offline fallback to the cached window. The trip planner (`src/trip/`) snapshots program events into the plan so it survives cache eviction; `trip/ics.ts` hand-rolls the ICS (Pacific VTIMEZONE, folded lines, stable UIDs, VALARM reminders on timed events, calendar-level X-WR-CALNAME) and `trip/exportTrip.ts` prefers Web Share with a File (iOS standalone PWA can't reliably download blobs) before falling back to an anchor download.
- **Trip board (`/trip`).** The plan renders as a calendar board (`components/TripAgenda.tsx` + `.css`), not a list: one full-width timeline per day of the trip window (empty days included, so they can be dropped onto), blocks positioned and sized from `trip/slotting.ts` output at a persisted px-per-minute zoom (`tfg.trip.density`), tinted per item by `trip/agendaItem.ts` (stop tones come from the map's `KIND_STYLES`, so a viewpoint is the same hue on the board and on `/map`; programs key off their category), and lane-packed by `trip/agendaLayout.ts` when two things overlap. Every block carries its coordinate and a directions deeplink. **Dragging is hand-rolled on pointer events, and the touch path is load-bearing:** a block's body is `touch-action: none`, because a block that lets the browser scroll has the gesture taken away mid-drag (Chrome fires `pointercancel` on the first move after the lift, which is exactly the failure this replaced), so the board scrolls those touches itself, fling included — do not "fix" that back to `pan-y`. Press-and-hold lifts on touch, 4 px of travel lifts with a mouse; dropping calls `placeItem` (one write for day + time) and pins the item so slotting stops moving it, and the bottom-edge handle calls `setItemDuration`. Arrow keys, Alt+arrows, and PageUp/PageDown are the keyboard equivalents. Day windows carry an hour of headroom past the first and last block (`dayWindowFor`), without which a drag has nowhere later to go and clamps straight back.
- **Calendar export.** Exactly one path, and deliberately so: the trip review's footer (`components/TripReview.tsx`) renders the plan to an `.ics` client-side and hands it to the OS through `trip/exportTrip.ts`. It is a one-time file, fully offline, and the copy says plainly that a later plan edit means saving the file again. The Google Calendar OAuth push (Worker `/api/calendar/google/*`, `trip/googleCalendar.ts`, `trip/calendarSync.ts`, the Account page's `CalendarCard`) and the hosted subscription feed (`/api/trip/feed`, `trip/feed.ts`, `trip/feedSync.ts`, the webcal/add-by-URL sheet) were both **removed** in July 2026 — do not reintroduce a server-side calendar integration without a decision to reverse that. Nothing about a buyer's calendar touches the Worker now, so there is no OAuth client to keep verified and no capability URL to revoke. Slotting travel buffers are distance-derived (`trip/slotting.ts`: haversine at a 22 mph park heuristic + park-and-walk, clamp 10-75 min, flat 30 when a coord is missing).
- **Service worker** (`public/sw.js`) caches the app shell + photos for offline use. The `UpdateBanner` component prompts when a new build is available; the "an update is waiting" fact is **latched in `pwa/registerSW.ts` module state** (`getPendingUpdate`/`onUpdateReady`), not delivered as a one-shot event, because an update found during boot fires before the banner subscribes and a remount used to drop it — both read as "the update bar disappeared". `registerSW` also reads `registration.installing` directly (the spec fires `updatefound` *before* `register()` resolves, so a listener attached in the `.then` misses the first one), keys "is this an update" off `registration.active` rather than `navigator.serviceWorker.controller` (a hard reload loads the page uncontrolled), and re-announces a still-waiting worker after every poll/focus `update()` — which is what brings the bar back if it was ever lost. **Hard invariant since the July 2026 audit:** an HTML response (the SPA `_redirects` 200 fallback) must never be cached under an asset/photo/tile/shell key — the SW and `useDownloads.fetchIntoCache` both guard with an `isHtml` check and treat such a response as a failed URL, and `activate` self-heals by purging HTML from the runtime and tile caches. Photo pre-warming goes through `pwa/precache.ts` (`PRECACHE_URLS` message, prod-only, works pre-controller via `serviceWorker.ready` with a 10 s timeout). The `beforeinstallprompt` event is captured at module level in `pwa/installPrompt.ts`, called from `main.tsx` **before render** (component listeners fire too late); `Welcome.tsx` and `InstallPrompt.tsx` consume it via `useDeferredInstallPrompt`. **iOS has no such event and never has**, so nothing can make Safari show an OS install dialog: the ask there is the app's own `components/InstallSheet.tsx`, which gives per-browser Add to Home Screen steps (`iosBrowser()` in `utils/platform.ts` tells Safari from Chrome/Firefox/Edge from an embedded webview, where installing is impossible and the only useful instruction is "open this in Safari"). `lib/install.ts` owns the two flags and `shouldAutoPrompt()`, whose claim is memoized in module state because a `useState` initializer runs twice under StrictMode and the banner remounts on every route change — either would burn the one unprompted open. Entry points: the sheet auto-opens once after onboarding, the banner's "Show me" reopens it, `/welcome` step 2 opens it (and claims the auto-open so Home doesn't ask again a tap later), and the Account page's `InstallCard` un-dismisses it for a buyer who tapped "Not now" and changed their mind. `vite.config.ts` pins React and the router into a `react-vendor` manual chunk so it survives shell re-precache across deploys.
- **Download packs** (`offline/useDownloads.ts`): live status and abort controllers are module state so in-flight downloads survive remounts; `verifyPack` tolerates a small missing fraction (5% for the tile pack) and records tolerated failures rather than demanding 100%.
- **Stop photos are a placeholder pass.** `public/photos/` reuses editorial-site images (several stops share the same photo); many stops still have no matching image and need dedicated photography before launch. An entry with none carries `photos: []` and renders the "Photo coming" tile. The one hard rule: **never wire a `src` at a file that is not in `public/photos/` yet.** ResponsivePhoto degrades to that same tile, so a dangling reference looks merely unfinished, but photo download packs carry `tolerateMissing: 0` (every photo is paid content), so one missing file makes its region's offline download fail permanently and blames the buyer's connection — which is exactly what three dangling srcs did to the Yosemite Valley pack until July 2026. `scripts/check-guide-photos.mjs` (in `npm --prefix scripts run check`; `run photos:check` for the full inventory) fails on a dangling src or a gap in a photo's responsive ladder, and warns on a photo with no `PHOTO_CREDITS` entry. Outstanding slots and the acquisition runbook: `scripts/data/guide-photo-manifest.json` and the photo-pass section of LAUNCH-READINESS.md.

## Worker architecture

Routes mounted in `workers/src/index.ts`:

- `/api/auth/login` — email + 6-digit code path, KV-backed buyer lookup. This is the real buyer sign-in: the PWA's `Login.tsx` tries it first and falls back to `/api/auth/dev-login` only on 401/429.
- `/api/auth/dev-login` — **active** username + code path, env-backed (`DEV_USERNAME`/`DEV_CODE`/`ADMIN_USERNAME`/`ADMIN_CODE`). Pre-Stripe; either pair issues a JWT.
- `/api/auth/exchange` — exchanges a magic-link `accessToken` for a JWT.
- `/api/checkout/*` — Stripe Checkout session start + inventory cap enforcement. The editorial `/guide` page still calls `/api/inventory` for the scarcity counter (which also returns `priceCents` and `renewalPriceCents`). `/start` accepts an optional gift body (`{gift, recipientEmail, giftNote}` → session `metadata.kind = 'gift'`; the webhook provisions the **recipient** and mails the payer a receipt). `/renew` starts a discounted renewal (`GUIDE_RENEWAL_PRICE_CENTS`): `POST` is JWT-gated for the PWA Account button, `GET ?token=<accessToken>` serves the emailed notices (rate-limited, 302 to Stripe); renewals bypass the monthly cap, extend `expiresAt` from max(now, current), and keep the buyer's token + code. A daily cron sweep (`lib/renewals.ts`) sends T-60/T-14/T-1 renewal notices, deduped per (email, stage) by KV sentinels.
- `/widget/conditions` + `/widget.js` — the free embeddable conditions box for gateway-business sites (live entrance waits proxied from the NPS S3 feed via `lib/waits.ts`, KV-cached 5 min, + a 3-day Valley fold of `weather:v1`). Mounted at the **root** level like `/tiles`, NOT under `/api/*`, because the API CORS middleware echoes allow-listed origins and embeds need `*`. The editorial `/widget` page is the pitch + snippet + live preview (its preview is why `api.thetalusfieldjournal.com` is in the CSP `script-src`).
- `/api/stripe/webhook` — Stripe webhook handler for `checkout.session.completed` (provisions a buyer record in KV — `expiresAt` = purchase + 548 days, a true 18 calendar months — and emails the access code) and `charge.refunded` (any refund, full or partial, revokes access by setting `expiresAt` and `refundedAt` to now; missing email or unknown buyer is logged for manual revoke, not failed). Idempotent via a `stripe_event:<id>` dedupe key. Sessions completed with `payment_status: 'unpaid'` (async payment methods) defer provisioning to `checkout.session.async_payment_succeeded`. All three events must be enabled on the Stripe webhook endpoint — see the DEPLOY.md launch checklist.
- `/api/contact` — editorial contact form backend (`page-newsletter-contact.jsx` posts here). Validates a fixed subject enum, uses a `website` honeypot field against bots, and relays via Resend (`lib/email.ts`).
- `/api/indexnow/submit` — bearer-token-gated POST that forwards a `{ urls: [...] }` list to api.indexnow.org. Push-indexes Bing / Yandex / Seznam / Naver / Yep in a single call. Use `scripts/indexnow-ping.sh` after publishing an article. Requires `INDEXNOW_KEY` and `INDEXNOW_ADMIN_TOKEN` secrets.
- `/api/programs?start=&end=` — **unauthenticated** merged park-program listings for a trip window (≤31 days): NPS Events API data from the `GUIDE_PROGRAMS` KV cache plus the hand-curated `src/data/manual-programs.ts` (Conservancy / Aramark / astronomy — the NPS API doesn't carry most partner events). A daily cron (`[triggers]` in wrangler.toml, `scheduled` export in `index.ts`) ingests a rolling 120-day window; the route self-heals with a live fetch + KV backfill when the cache is missing or >48h old. Needs the `NPS_API_KEY` secret (free, developer.nps.gov); without it the feed serves manual curation only. Seasonal curation workflow: edit `manual-programs.ts` (zod-validated at load), `wrangler deploy`.
- `/api/trip/plan` — the PWA's cross-device sync (`routes/trip.ts`). GET/POST/DELETE, all JWT-gated, KV keyed by sub, 60 writes/hour, 256 KiB cap. Whole-document last-write-wins on the client's `updatedAt`. **The Worker never parses the document**: the trip schema lives in `apps/guide/src/trip/schema.ts` and evolves with the app, so a server-side mirror would mean a Worker deploy per planner change and a stale mirror would start rejecting valid plans. The Worker owns the envelope, the size, and the write rate; the PWA re-validates on read (`apps/guide/src/sync/schema.ts`, salvage-on-partial-corruption). Opt-in and off by default.
- `/api/push/*` — web push for the PWA (`routes/push.ts`, `lib/push.ts`, `lib/pushSweep.ts`). `GET /key` serves the public VAPID key, `POST /subscribe` and `DELETE /subscribe` are JWT-gated device registration, and `POST /pending` is **unauthenticated on purpose**: it is called from the service worker's push handler, which has no access to localStorage and therefore no token, and the 100+ character push endpoint it presents is already the capability that lets anyone push to that device. Pushes are **payload-less** — RFC 8291 payload encryption is the riskiest code this Worker could hand-roll and fails as "notifications silently stop", so the woken SW asks what the push was about instead. VAPID ES256 signing IS implemented (WebCrypto emits raw r||s, exactly what JWS wants). Needs `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` secrets (`node scripts/gen-vapid-keys.mjs`); without them every route 503s and the app hides the opt-in. The daily cron sends exactly two notices (`sweepPush`): a morning-of nudge on each trip day, and renewal heads-ups at T-14/T-1. Trip dates are the one piece of planner state that reaches the server outside the opaque sync doc, because a morning nudge cannot be scheduled without them.
- `/api/trip/email` — **unauthenticated** editorial trip-link mailer (`routes/trip-email.ts`; mounted before `/api/trip` on purpose). POST `{email, stops, website}` from the editorial map's TripEmailBox; `website` is a honeypot (non-empty → fake 200). Validates and dedupes stop ids (≤30, `[a-z0-9-]`), builds the `/map?trip=…` URL server-side (so it can't mail arbitrary links), sends via Resend (`sendTripLink` in `lib/email.ts`), and rate-limits to 5 sends/hour per SHA-256-hashed IP in `GUIDE_BUYERS` KV.
- `/api/weather` — **unauthenticated** NWS forecast proxy (`routes/weather.ts`, `lib/weather.ts`). No params; returns all four fixed park spots (ids match the PWA Region enum). Two-step api.weather.gov fetch (points → gridpoint forecast), keyless (User-Agent required, no secret). Cached in `GUIDE_PROGRAMS` KV (`weather:v1`, plus a gridpoint-URL cache); the route refreshes inline when the record is missing or >2 h old and a failed spot keeps its stale copy; responses carry `max-age=900`. The daily cron also calls `refreshWeather` as a floor. The zod schema is hand-mirrored in `apps/guide/src/weather/schema.ts`.
- `/api/waits` — **unauthenticated** live entrance waits for the PWA (`routes/waits.ts`). Serves the same display shape as the widget via the shared `waitsDisplay` in `lib/waits.ts` (KV-cached 5 min by `getWaits`; stale or missing entrance → `minutes: null`); a dead feed serves `{fetchedAt: null, waits: []}`, never an error. Mounted under `/api/*` on purpose (unlike `/widget`): the PWA's `apiFetch` sends preflighted headers, which the origin-echo CORS middleware answers.
- `/api/inventory` also returns `priceCents` (from `GUIDE_PRICE_CENTS` in wrangler.toml) — the editorial buy box renders it live, so the price is edited in exactly one place.

Both auth paths sign the same JWT shape (`{ sub, iat, exp }`, HS256, 90-day TTL) using `MAGIC_LINK_SIGNING_SECRET`. The `sub` claim carries an email for `/login` and a username for `/dev-login` — the PWA doesn't care which.

CORS in `index.ts` allow-lists the editorial origin, the PWA origin, and `http://localhost:5173`/`5174`/`8000` for local dev. Add new dev origins there.

## Brand & voice

The brand is **The Talus Field** (formerly "Yosemite Sentinel"). The editorial voice is dry, declarative, journalistic — no marketing fluff, no exclamation marks. House style replaces em-dashes in reader-facing copy with commas, colons, or periods; a deliberate sweep removed them from article bodies, so don't reintroduce them when writing copy. Match the existing tone.

## Things that have surprised past edits

- **PRs here get merged fast, sometimes while a session is still pushing.** PR #219 was merged within a minute of creation; a follow-up commit pushed to the branch afterwards sat stranded on the closed PR and never deployed. Before pushing more commits to a branch that already has a PR, check the PR's state first. If it is merged: rebase the new commits onto `origin/main`, force-with-lease push, and say plainly that a **new** PR is required to ship them — never assume a push to an existing branch will deploy. `.github/workflows/stranded-commits.yml` backstops this: it fails the push and comments on the merged PR when it detects the pattern.
- **The homepage's LCP element is text, not the hero photo.** Measured in July 2026 on a throttled phone: the `.hero__dek` paragraph, not the plate. Preloading the hero image bought nothing at the top of the page and was removed from `index.html` (it was firing on every route). If you are tuning homepage vitals, measure which element LCP actually is before optimising an image.
- Below the Start Here row the homepage mounts on scroll (`DeferredSection` in `page-home.jsx`, `IntersectionObserver` with a 600px margin, fails open). That was a TBT fix — the homepage was spending ~1.7s on the main thread against ~150ms on an article page. Anything moved above that boundary starts costing first-paint time again; anything below it must not be a scroll target, which is why Start Here (the first hero door scrolls to it) stays eager.
- The editorial site has **no test suite, lint, or typecheck** — runtime errors only surface in the browser. The pre-commit guards are `npm --prefix scripts run check` (cache-busters + SEO mirrors + prerender + compiled-dist freshness in one command) plus the offline battery `npm --prefix scripts run checks`.
- `DEPLOY.md` was refreshed in the July 2026 launch-prep pass and now matches the region-based model (four regions, 66 stops incl. hidden). If a runbook step contradicts the code, trust the code and fix the doc.
- **The guide is a paid product ($3.99 one-time, 18-month access), flipped to on-sale in the July 2026 launch-prep pass.** `page-guide.jsx` has `GUIDE_ON_SALE = true`: it renders `GuideBuyBox` (POSTs `/api/checkout/start` and reads the price from `/api/inventory`; `GUIDE_PRICE_CENTS = "399"` in `workers/wrangler.toml` is the single source of truth). `GuideWaitlistBox` (Buttondown capture tagged `guide-waitlist`) stays in the file for any future sales pause; flip the flag back to restore it. The old `GUIDE-LAUNCH` markers are historical breadcrumbs now — the whole editorial flip set (footer link, noscript link, robots, sitemap, llms.txt) has landed. **Merging to `main` puts the buy button in front of readers**, so the ops gate in LAUNCH-READINESS.md (secrets, Stripe webhook with both events, Resend domain verification, test-mode purchase) must be cleared first; the runbook is in DEPLOY.md. `/api/auth/dev-login` remains the operator door; rotate `DEV_*` creds before launch.
- The masthead issue label (`window.SITE.issue` / `issueDetail` in `data.js`) derives its month from the current date at runtime — don't hard-code a month name into masthead copy.
- `points.geojson` carries its own `?v=` cache-buster (`POINTS_URL` in `page-map.jsx`), separate from the shared `?v=N` that all page scripts use; editing pins without bumping it ships stale map data.
- The PWA service worker will happily serve a cached SPA-fallback HTML page as a photo, tile, or the shell if the `isHtml` guards are removed — this bricked offline launch once. Treat "never cache HTML under a non-navigation key" as an invariant when touching `sw.js` or `useDownloads.ts`.
- PWA stop photos look wired up but are placeholders recycled from the editorial site; several stops share the same image and the comment block at the top of `stops.ts` documents this.
