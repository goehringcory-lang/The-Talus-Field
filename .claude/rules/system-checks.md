# The system checks battery and its nightly run

Moved from the root CLAUDE.md (Editorial site conventions); loads when a matching file is touched.

- **System checks suite.** `scripts/system-checks.mjs` (run via `npm --prefix scripts run checks`) is a health battery with one module per check in `scripts/checks/` (links, per-page SEO + og:image + Article JSON-LD, sitemap, feed, image hygiene, mirror freshness, template smoke, email-auth, API Worker health). It exits non-zero only on **error**-severity findings; length/size/keyword issues are **warnings**. Offline by default; `--online` adds link liveness, sitemap 200s, the template smoke test, SPF/DKIM/DMARC DNS lookups, and the API probes. `--only=<slug,slug>` runs a subset (slugs are the module names: `api`, `deploy-parity`, `links`, `email-auth`, …), which is what `run api:check` uses. **`checks/deploy-parity.mjs` is the editorial Worker's stale-deploy detector** (see the first bullet under "Things that have surprised past edits"): it reads the Worker's own catalog off `/.well-known/talus-build.json` and errors when the asset layer serves an article the Worker bundle does not know. **`checks/api.mjs` is the only module that looks at `api.thetalusfieldjournal.com`**, and it exists because that Worker shipped by hand from `workers/` until September 2026, so it was simultaneously the least-watched surface and the one holding checkout, the Stripe webhook, the buyer records and the renewal sweep. Now that it deploys through a gated Workers Build, the same check is how a **failed** build surfaces, since a red build ships nothing and leaves the old version answering. Its stale-deploy detector is repo parity: `/api/inventory` echoes `priceCents` and `renewalPriceCents` straight out of `[vars]` in `workers/wrangler.toml`, so a live number that disagrees with the file means the deployed Worker predates the repo, and that is an **error** (so is a live `cap` field: the monthly sales cap was removed in September 2026, and a Worker still reporting one will turn buyers away at it) — the same class of silent regression the editorial Worker hit twice in Aug 2026, which took a human noticing 404s to catch. Severity follows the site's posture: anything that breaks a **sale** is an error (API unreachable, stale price, CORS stops echoing the editorial origin so the buy box's fetch dies in the browser while curl still sees 200), while the read-only feeds render nothing rather than an error by design and so only ever **warn** — including the one that is an editorial deadline rather than an outage, an empty `/api/programs` fortnight meaning the ~5-weekly Guide-edition curation in `manual-programs.ts` has lapsed. Point it at a local Worker with `--api-base=`. The catalog loaders are shared with `gen-seo-artifacts.mjs` via `scripts/lib/catalog.mjs` (one `node:vm` harvest of `data.js`). It runs nightly in CI (`.github/workflows/system-checks.yml`), which also records a Lighthouse Core Web Vitals trend to `scripts/data/lighthouse-history.json` (warn-only on regression). New-URL search-engine notification is **not** here — `indexnow.yml` already push-indexes on publish, and standalone Google/Bing sitemap pinging was retired in 2023. The committed baseline is `scripts/data/baseline-report.md`.
