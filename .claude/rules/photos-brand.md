# The brand mark, icon generators and both photo pipelines

Moved from the root CLAUDE.md (Editorial site conventions); loads when a matching file is touched.

- **The brand mark and the icons derived from it (August 2026).** `img/talus-field-mark.png` is the master illustration, and two generators read it: `scripts/gen-brand-icons.mjs` (`npm --prefix scripts run brand`) writes the editorial set — the JSON-LD publisher logo `talus-field-mark-square.png`, the `favicon-*.png` ladder, `apple-touch-icon.png`, `favicon.ico`, `mark-192.png` for the trip-share email, and `talus-field-mark-masthead.png`, the 168 px cut the masthead draws — and `apps/guide/scripts/generate-icons.mjs` writes the PWA set. Run **both** after replacing the mark. The editorial generator exists because that set used to be made by hand and silently went stale: a mark swap left the favicons carrying the previous canvas, illustration shrunk to half the frame. Three things are load-bearing: (1) both generators `.trim()` the source, so what matters is the illustration, not the canvas it was exported on — the August 2026 swap recropped the canvas only, which is why it changed every editorial icon and **no** PWA icon (verified pixel-identical, so nothing was renamed); (2) the PWA's output filenames are versioned (`.v2`) because the service worker's runtime cache is unversioned and its install step skips any URL it has already cached, so art replaced at an existing URL never reaches an installed client — if a rerun changes those bytes, rename and update `manifest.webmanifest`, `apps/guide/index.html`, `sw.js` (`RUNTIME_PRECACHE` plus the push icon/badge) and the components rendering the lockup; (3) the editorial masthead and the `favicon-*.png` links carry their **own** `?v=` counter, separate from the shared script version, because `/img/*` is served `immutable, max-age=2592000` — without it a repeat visitor keeps the old mark for a month. `favicon.ico` needs none (`_headers` gives it a one-day TTL), and the 512 archive pages deliberately link the mark unversioned, the same trade-off already made there for `/styles.css`. **Never point a page at the master itself (September 2026).** `talus-field-mark.png` is 805 × 622 and 567 KB; until September 2026 the masthead (and so every page view, plus each of the 569 archive pages) downloaded it to draw a 56 px logo, which made it the largest transfer on the site, ahead of the hero image it competed with. `Header` now loads `talus-field-mark-masthead.png` (214 × 168, about 23 KB) with `width`/`height` set to the file's pixels so the box keeps its aspect ratio before the bytes arrive, and the archive's 40 × 40 box takes `favicon-96.png`, the square cut, which also stopped squeezing the 1.28:1 illustration into a square. If the trimmed mark's aspect ratio ever changes, the `width`/`height` on that `<img>` in `components.jsx` change with it.
- **Licensed photo acquisition (September 2026 photo pass).** `scripts/fetch-guide-photos.mjs` pulls license-safe candidates from Wikimedia Commons per manifest slot, a human (or a contact sheet and a multimodal review) picks one, and `select` normalizes it and records author/license/source. Two targets share the script: the default fills `apps/guide/public/photos/` from `scripts/data/guide-photo-manifest.json` and writes `photo-credits.json` (then `emit-credits` regenerates `photoCredits.ts`); `--target=editorial` fills `img/` from `editorial-photo-manifest.json` and writes `editorial-photo-credits.json`, whose entries you copy by hand into the article's `credit` string in `data.js` (`Photo: Author / Wikimedia Commons (CC BY 2.0)`). Public domain and CC0 first; a CC BY file is fine because both surfaces render the credit. Three source quirks are encoded in the script and must not be undone: the API answers a burst with 429 + Retry-After (retried, not dropped), `upload.wikimedia.org` throttles original-file downloads for ten minutes at a time while `/thumb/` keeps serving (every download is a thumbnail URL), and anonymous thumbnails exist only at bucket widths (`THUMB_WIDTH` is 1920 and must stay a bucket). A replaced photo always gets a **new filename**: `/img/*` is immutable for 30 days and the PWA service worker never refetches a URL it has cached. Four guide entries still carry an honest stand-in (Carlon Falls, Evergreen Lodge, Little Nellie Falls, Hidden Lake): Commons has nothing for them, and the caption says what the photo shows.
- **Photo ingest (house photography).** `scripts/ingest-photos.mjs` (`npm --prefix scripts run photos:ingest`) is the front door for photos shot by the owner; `fetch-guide-photos.mjs` remains the path for licensed Commons/Pexels acquisition. Drop camera files into the gitignored `photo-inbox/editorial/` (→ `img/`) or `photo-inbox/guide/` (→ `apps/guide/public/photos/`), then run the one command: it applies EXIF orientation, downscales, re-encodes as mozjpeg with **all metadata stripped**, runs the variants generator, records an "All rights reserved" credit for guide photos, and prints the `data.js` / `stops.ts` snippet. Four rules it enforces, each for a reason that bit or would have bitten: (1) `gen-responsive-images.mjs` never calls `.rotate()`, so a portrait phone photo dropped straight into `img/` comes out sideways in every variant — everything in the repo today was pre-normalized by `fetch-guide-photos.mjs`, which is why nothing has hit it yet; (2) both photo dirs deploy **wholesale, originals included**, so un-stripped EXIF publishes the camera's GPS fix — capture coords are logged to the gitignored `scripts/data/photo-exif-log.json` first, since they're useful for checking a stop's `coord`, and then destroyed by the re-encode; (3) camera-default filenames (`IMG_4823`) are skipped, because the pipeline has no manifest and the filename becomes the permanent URL key and the reference in `stops.ts`; (4) an existing target filename is an error without `--replace`, because `/img/*` is served `immutable, max-age=2592000` and reusing a name means up to 30 days of the old photo. `--dry-run` reports without writing. **Shoot JPEG, not HEIC** (iPhone: Settings > Camera > Formats > "Most Compatible"): sharp's prebuilt libvips omits the HEVC decoder, verified July 2026 against a real HEVC file. The trap is that nothing cheap detects it — `sharp.format.heif.input.file` reads `true` (the HEIF loader exists, for AVIF), and `metadata()` *succeeds* on a HEIC and reports `compression: 'hevc'`; only the pixel decode fails. The ingest checks `compression` and skips with instructions, and wraps the write so an undecodable file can't take down a batch. **Remote path (August 2026):** the same ingest also runs from `.github/workflows/photo-import.yml`. Photos uploaded from a phone via the Worker's `/photos` page stage untouched in the `talus-photo-inbox` R2 bucket (`workers/src/routes/photos.ts`, bearer-gated by `PHOTO_UPLOAD_TOKEN`; camera-default names and HEIC are rejected at upload); the workflow (triggered by `POST /api/photos/import` via `repository_dispatch`, or manually) pulls them into `photo-inbox/`, runs `ingest-photos.mjs`, and opens a PR with the ingest log and reference snippets — ingested files are cleared from the inbox, skips stay staged. The Worker never writes a photo anywhere the site serves from; setup runbook is in DEPLOY.md ("Remote photo upload").
